# 个人费用支出管理系统 - 系统设计文档

## 一、产品概述

### 1.1 产品定位

面向经常出差的职场人士，提供发票管理、费用报销、出差补贴管理的一站式解决方案。通过 H5 技术开发，封装为微信小程序，免安装即用，同时支持 PC 端浏览器访问。

### 1.2 核心痛点

| 痛点 | 解决方案 |
|------|---------|
| 发票多、整理麻烦 | PDF 发票拖入即自动解析，生成待报销记录 |
| 忘记报销导致损失 | 待报销提醒 + 统计面板，一目了然 |
| 出差补贴容易遗漏 | 出差日期自动计算补贴天数 |
| 报销单手工制作繁琐 | 一键生成标准报销单 PDF |
| 报销时还要逐个翻找发票 | 报销单+全部发票原件一键打包导出，直接交财务 |

### 1.3 目标用户

- 经常出差的企业员工
- 自由职业者 / 个体经营者
- 需要管理个人支出的职场人士

### 3.2 用户模块

#### 3.2.1 注册 / 登录

- **微信授权登录**：小程序环境直接获取微信授权（主流程）
- **手机号登录**：H5 / PC 端通过手机号 + 短信验证码登录
- **邀请码绑定**：注册时可填写邀请码，绑定推荐关系

#### 3.2.2 个人中心

- 个人资料编辑（头像、昵称、公司名称、部门）

- 我的邀请（邀请记录、返佣统计）
- 设置（通知偏好、默认补贴标准）

### 3.3 费用管理模块

#### 3.3.1 发票管理

**核心交互流程：**

```
用户拖入/选择 PDF 发票
        │
        ▼
  上传至服务器 (MinIO)
        │
        ▼
  异步解析发票 (PDFBox)
  ┌─────┴─────┐
  │ 解析字段:  │
  │ · 发票号码 │
  │ · 发票代码 │
  │ · 开票日期 │
  │ · 金额(含税)│
  │ · 税额     │
  │ · 销方名称 │
  │ · 购方名称 │
  │ · 发票类型 │
  └─────┬─────┘
        ▼
  生成「待报销」支出记录
        │
        ▼
  用户确认/修改信息
```

**发票解析策略：**
- 电子发票 PDF：使用 PDFBox 提取文本，正则匹配关键字段
- 增值税发票：识别发票代码、号码、金额、税额等标准字段
- 火车票/机票：识别出发地、目的地、金额、日期
- 解析失败时：提示用户手动填写关键信息（金额、发票号必填）

**发票分类：**

| 类别 | 说明 |
|------|------|
| 交通费 | 机票、火车票、出租车、网约车 |
| 住宿费 | 酒店发票 |
| 餐饮费 | 餐厅发票 |
| 办公费 | 办公用品发票 |
| 通讯费 | 电话费发票 |
| 其他 | 用户自定义类别 |

#### 3.3.2 出差补贴管理

```
创建出差记录
├── 出差目的地
├── 出差开始日期
├── 出差结束日期
├── 补贴标准 (元/天，可在设置中配置默认值)
└── 自动计算
    ├── 出差天数
    └── 补贴总金额 = 天数 × 标准
```

#### 3.3.3 手动添加费用

- 支持手动创建费用记录（无发票场景）
- 必填：金额、日期、类别
- 选填：描述、关联出差记录

### 3.4 报销模块

#### 3.4.1 报销单生成 & 打包导出

**核心理念**：生成报销单后，一键将**报销单 + 所有电子发票原件**打包导出，直接交给财务，彻底省去手动整理发票和填写报销单的步骤。

**操作流程：**

```
  选择待报销的费用项
  (多选：发票费用 + 补贴)
        │
        ▼
  输入报销信息
  ├── 报销单标题 (如: 2026年3月北京出差)
  ├── 备注说明
  └── 关联出差记录 (可选)
        │
        ▼
  预览报销单
        │
        ▼
  确认生成
        │
        ├── 1. 生成报销单 PDF（封面页 + 费用明细表）
        │
        ├── 2. 自动收集所有关联的电子发票原件 PDF
        │
        ├── 3. 合并为一个完整 PDF 文件
        │      报销单(封面) + 发票1 + 发票2 + ... + 发票N
        │
        └── 4. 同时生成 ZIP 打包文件（备选）
               ├── 报销单_RB202603150001.pdf  (报销单)
               ├── 01_交通费_火车票_¥580.pdf   (发票原件)
               ├── 02_住宿费_酒店_¥450.pdf     (发票原件)
               ├── 03_餐饮费_工作餐_¥120.pdf   (发票原件)
               └── 发票清单.xlsx               (Excel明细)
        │
        ▼
  导出方式选择
  ├── [导出合并PDF]  → 一个PDF = 报销单 + 全部发票（推荐，最方便）
  ├── [导出ZIP压缩包] → 报销单 + 发票原件 + Excel清单（独立文件）
  ├── [仅导出报销单]  → 只导出报销单PDF
  └── [发送到邮箱]    → 将打包文件发送到指定邮箱
        │
        ▼
  状态变为「已提交」
```

**导出的核心价值：**
```
┌─────────────────────────────────────────────────────────────┐
│  以前的报销流程 (痛苦)：                                     │
│  1. 翻手机找各种发票 PDF                                     │
│  2. 逐个下载到电脑                                           │
│  3. 手动填写报销单（发票号、金额、分类...）                    │
│  4. 把报销单和发票一起整理好交给财务                           │
│  → 耗时 30-60 分钟                                           │
│                                                              │
│  现在的报销流程 (爽)：                                        │
│  1. 平时发票 PDF 随手拖进系统（自动解析）                      │
│  2. 报销时勾选 → 点「导出合并PDF」                            │
│  3. 一个文件发给财务，里面报销单+全部发票都有了                │
│  → 耗时 2 分钟                                               │
└─────────────────────────────────────────────────────────────┘
```

#### 3.4.3 ZIP 压缩包内容结构

为满足部分财务要求发票原件独立存放的场景，同时提供 ZIP 打包导出：

```
报销单_RB202603150001_张三_2026年3月北京出差.zip
│
├── 报销单_RB202603150001.pdf           ← 报销单（同上封面页）
│
├── 发票/                               ← 全部发票原件（按序号+类别命名）
│   ├── 01_交通费_火车票_¥580.00.pdf
│   ├── 02_住宿费_酒店发票_¥450.00.pdf
│   └── 03_餐饮费_工作餐_¥120.00.pdf
│
├── 发票清单.xlsx                        ← Excel 明细表（方便财务核对）
│   (内容: 序号/类别/发票号/金额/日期/备注)
│
└── 合并版_全部文件.pdf                  ← 合并PDF（报销单+全部发票）
```

#### 3.4.4 不同发票类型的处理

| 费用类型 | 有发票原件 PDF | 导出处理方式 |
|----------|--------------|-------------|
| 发票费用（已上传 PDF） | 有 | 自动附加发票原件到合并 PDF，同时放入 ZIP |
| 出差补贴 | 无 | 仅在报销单明细表中列出，不附加文件 |
| 手动录入费用（无发票） | 无 | 仅在报销单明细表中列出，备注标记「无发票」 |
| 手动录入费用（有截图/照片） | 有（图片转PDF） | 图片自动转为 PDF 后附加 |

#### 3.4.5 报销状态流转

```
待报销 ──→ 已生成(生成报销单) ──→ 已导出(导出打包文件) ──→ 已收款 ──→ 完成
              │                      │                      │
              │                      │                      └── 点击「已收钱」
              │                      └── 可多次导出（合并PDF/ZIP/邮件发送）
              └── 可继续编辑报销单（增删费用项）
```

#### 3.4.6 邮件发送功能

支持将打包文件直接发送到财务邮箱，免去手动转发：

```
点击「发送到邮箱」
        │
        ▼
  填写收件信息
  ├── 收件邮箱 (可保存常用财务邮箱)
  ├── 邮件标题 (默认: 费用报销单_张三_2026年3月北京出差)
  └── 附加说明 (可选)
        │
        ▼
  发送邮件
  ├── 邮件正文：报销单摘要信息
  └── 附件：合并PDF 或 ZIP (用户选择)
        │
        ▼
  发送成功 → 记录发送日志
```

### 3.6 会员 & 收费模块（优化版）

> **优化思路**：原方案仅有「免费试用 30 天 → 年费 99」单一路径，存在以下问题：
> 1. 付费门槛过高——从免费直接跳到年付 99，用户心理落差大，转化率低
> 2. 没有「永久免费层」——不付费就完全不能用，无法积累免费用户作为裂变基数
> 3. 没有差异化权益——付费与免费的体验差距没有梯度，无法制造「够用但不够爽」的卡点
> 4. 缺少团队/企业场景——出差报销天然是公司行为，缺少团队批量采购入口
>
> 优化后采用 **「永久免费 + 月付尝鲜 + 年付主推 + 团队版」** 四层漏斗模型。

### 3.7 裂变增长引擎（优化版）

> **优化思路**：原方案的裂变机制问题：
> 1. 单一返佣模式——只有「推荐付费返 19 元」一种激励，动力不足
> 2. 只奖励推荐人——被推荐人没有任何好处，接受意愿低
> 3. 传播链条短——只有一级分销，传播深度有限
> 4. 缺乏即时反馈——推荐后需要等对方付费才有收益，周期太长
> 5. 分享素材单一——只有文案模板，没有社交货币属性
>
> 优化后构建 **「双向激励 + 二级裂变 + 游戏化成长 + 场景触发 + 社交货币」** 五维裂变引擎。

## 九、安全设计

| 安全项 | 措施 |
|--------|------|
| 接口认证 | JWT Token + Refresh Token 双 Token 机制 |
| 数据加密 | 敏感数据 AES 加密存储，传输全程 HTTPS |
| 文件安全 | 文件上传类型校验、大小限制(单文件10MB)、病毒扫描 |
| 接口限流 | Redis 令牌桶限流，防止恶意请求 |
| SQL 注入 | MyBatis 参数化查询，禁止拼接 SQL |
| XSS 防护 | 输入输出转义，CSP 策略 |
| 支付安全 | 签名验证、幂等处理、金额二次校验 |
| 数据隔离 | 用户数据严格按 user_id 隔离 |

```
     ├── B 获得：45天试用 (多15天) + ¥5新人券
     ├── A 获得：+5积分 + 通知「好友已注册」
     │
     ├── B 使用产品 → 体验核心价值
     │
     ├── B 付费 (可使用¥5新人券 + 邀请专属价¥89)
     │   │
     │   ├── A 获得：一级返佣 ¥19 + 20积分
     │   │   (返佣进入冻结余额，7天无退款后自动结算)
     │   │
     │   ├── 若A是被C邀请的：
     │   │   └── C 获得：二级返佣 ¥5 + 5积分
     │   │
     │   └── A 的推广等级经验值 +1
     │       · 累计3人付费 → 升级银牌 (解锁续费返佣)
     │       · 累计10人付费 → 升级金牌 (一级返佣涨至¥22)
     │       · 累计30人付费 → 升级钻石 (一级返佣涨至¥25)
     │
     └── B 续费时
         └── A 获得：续费返佣 ¥10 + 10积分 (银牌以上)
```
